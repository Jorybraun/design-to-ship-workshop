# Workshop conventions

- `website/` is the React workshop reference site. Phase lesson pages in `phase-1-idea/`, `phase-2-spec/`, `phase-3-prototype/`, `phase-4-plan/`, `phase-5-build/`, and `phase-6-ship/` are plain HTML with vanilla JavaScript; do not migrate them to React.
- Open a phase's `index.html` directly in a browser; no build or development server is required. Keep the workspace layout intact because lessons reference `website/src/index.css` and `website/public/cognition-mark.svg`. Google Fonts requires network access; system fonts are the fallback.
- Markdown lesson materials and the copyable HTML blocks must agree. Phase 2 `SPEC.md` and Phase 3 `DESIGN.md` are illustrative expected outputs, not approved application artifacts or evidence of a generated conference prototype.
- Run `python3 phase-2-spec/test_materials.py` from the workspace root to check all six phases' mirrored prompts/output, the skills chapter's pinned references, local links/assets, accessible references, Phase 2 fixture consistency, Phase 4 coverage, and Phase 5/6 handoff and release contracts. This uses only the Python standard library. It is internal maintenance tooling, not a participant activity.
- `phase-6-ship/` teaches separate source publication and artifact deployment, hosted smoke checks and recovery/maintenance ownership. Its `RELEASE.md` stays illustrative, not a live release log. Never weaken secure mode or organizational controls for native hosting; verify current capabilities and obtain deployment approval. The workshop repository is not proof of a public hosted site.
- Public source publication uses an explicit reviewed file list. Exclude `outputs/`, dependencies, build output, caches, environment files and local agent configuration. Only the individually reviewed `.devin/skills/design-system-foundations/SKILL.md` is included from `.devin/`. No workshop-wide license has been selected. `README.md` identifies the current lesson sequence and labels older reference material.
- `phase-5-build/` teaches context and document drift, fresh-session intake, separately authorized one-ticket implementation/review, optional cloud handoff and PRs. Its `HANDOFF.md` is illustrative and not an execution or approval record. Built-in `/handoff` can send conversation and work-in-progress changes; review tracked/untracked transfer scope and authorize cloud launch separately. Manual handoff does not automatically transfer laptop state. Authoring the lesson does not authorize cloud sessions, Git mutations, PR publication, tracker updates, or deployment.
- `phase-4-plan/` teaches architecture, ticket decomposition, read-only Linear MCP preflight, and separately authorized publication. Its `PLAN.md` is illustrative, not an approved architecture or live backlog. The lesson includes the workshop-wide Devin feature map; stacked PRs are optional and distinguish native GitHub.com stacks from ordinary dependent branches. Do not configure integrations, create issues, assign agents, push, open PRs, or merge merely because the lesson describes those actions.
- `skills/index.html` is a plain-HTML companion chapter; it summarizes Matt Pocock's skills at a pinned commit and labels workshop adaptations. Do not silently install upstream skills or run their tracker/file side effects. Our project-local `design-system-foundations` is workshop-authored, not Matt's.
- Phase 3 teaches MCP with a read-only Figma preflight and explicit target/write authorization. The HTML alternative needs no Figma connection. Authoring the lesson does not authorize creating remote designs.
- For lesson UI changes, check 1440px and 375px viewports, expanded content overflow, disclosure controls, checklist completion and reversal, copy success and denied-clipboard fallback, and browser console errors. Static tests do not replace browser checks.
- Phase checklists record human review only; they do not inspect a brief or grant implementation approval. Keep example decisions and actual participant approval distinct.
